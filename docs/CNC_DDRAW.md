# cnc-ddraw — разбор и как мы его используем (06.11.2026)

**Что это:** https://github.com/FunkyFr3sh/cnc-ddraw — MIT, релиз v7.1.0.0 (zip sha256 0b13ab89…bb908, 2.6 МБ). Подменная `ddraw.dll` (32-бит) для 2D-игр на DirectDraw: рисует через GDI / OpenGL / Direct3D 9 (авто), даёт окно без рамки, оконный режим, Alt+Enter, шейдеры-апскейлеры (catmull-rom, FSR, xBR…), лимит кадров, VSync, масштаб мыши, фикс чёрного экрана/вылетов/Alt+Tab. **Divine Divinity в списке поддерживаемых**, в `ddraw.ini` есть готовый профиль `[div]` (`resolutions=2`, `singlecpu=false`).
**Ограничения:** только DirectDraw (не Direct3D-игры); игра должна быть в «полноэкранном» режиме (окно включает сама обёртка).

## Конфликт с dgVoodoo
Оба — это `ddraw.dll` в папке игры (у dgVoodoo ещё D3DImm/D3D8/D3D9). Одновременно быть не могут. Правило в `Core` (`src/Cnc.cs`, `src/Program.cs`):
- включили cnc-ddraw → dgVoodoo отключается (его файлы только переименовываются в `*.dgvoff`, ничего не теряется); включили dgVoodoo → cnc-ddraw снимается (его файлы удаляются, настройки `ddraw.ini` сохраняются в `%APPDATA%\GameRemix\games\<id>\cnc\`);
- `Core.Dgv` = «есть DDraw.dll и это не cnc» (`Core.Cnc` определяется по строке «cnc-ddraw» внутри dll); чужая `ddraw.dll` откладывается в `ddraw.dll.ogfbak` и возвращается при выключении;
- «Откатить всё» возвращает оба в исходное состояние (`RevertCnc` внутри `RevertDgv`).

## Что встроено
`shared/cnc-ddraw/` (общее для всех игр): `ddraw.dll.gz`, `ddraw.ini.gz`, `shaders.bin.gz` (nearest, interpolation/*, xbrz/*), `LICENSE.txt.gz` — лицензия (копия кладётся в папку игры как `cnc-ddraw LICENSE.txt`), сборка `build_assets.py`. Ресурсы `ccd_*` в exe (+0.5 МБ). Оригинальный `cnc-ddraw config.exe` (4.9 МБ) НЕ встроен — наше окно «Настройки cnc-ddraw» (`CncForm`) правит `[ddraw]` в `ddraw.ini`: режим (без рамки / полный экран / окно), фильтр (чётко / плавно / мягко / FSR — шейдеры требуют OpenGL, форма сама ставит `renderer=opengl`), пропорции, VSync, движок отрисовки. Первое включение: `windowed=true, fullscreen=true, maintas=true` (без рамки, пропорции сохраняются).
UI: строка «cnc-ddraw» (Выкл/Вкл) под dgVoodoo; кнопка «Качество графики → Настроить» открывает форму той обёртки, которая сейчас включена. CLI: `--cnc on|off`.

## Для других игр
Список поддерживаемых игр (README) и секции `[имя_exe]` в `ddraw.ini` — это готовые профили. Для новой игры: проверить, что она DirectDraw (не D3D), добавить `games/<id>` переключатель «cnc-ddraw» (тот же `Core.SetCnc`, `Core` уже не привязан к Divine, кроме имени exe в профиле), при необходимости дописать профиль `[exe]` в `ddraw.ini`. Из кандидатов (HoMM3, Fallout 1/2, Gothic, Max Payne, GTA…) cnc-ddraw явно упомянут для HoMM2/3/4, Fallout 1/2, GTA 1/London, Baldur's Gate, Diablo 1/2, StarCraft, C&C, AoE, Heroes Chronicles и др.
Не проверено вживую: запуск Divine Divinity с cnc-ddraw на этом ПК не делался (полноэкранный режим не снимается, оконный владелец запретил). Проверены переключения и файлы на копии, окна на снимках.

## Почему с Divine Divinity падало, и как исправлено (06.11.2026)
Снят отладочный журнал (cnc-ddraw-experimental-debuglog.zip): `Exception C0000005 at slash1.dll+0x1EC0` сразу после `IDirectDraw::QueryInterface(IID_IDirect3D3)` + `IDirect3D3::EnumDevices` (у cnc-ddraw — NOT_IMPLEMENTED). Игра грузит один из четырёх рендерер-DLL по `slashed.cfg` (4 байта): 0 = Direct3D 6 (slash1.dll, slashed-d3d6.cfg), 1 = Glide (slash2), 2 = DirectX (slash3), 3 = Software (slash4, slashed-software.cfg). У владельца был 0 (D3D6; его обслуживает dgVoodoo), а cnc-ddraw умеет только DirectDraw (README: «game must have a DirectDraw (Software) renderer»; то же в их issue #119). Баг-репорт #157 (крэш на 2560x1440) лечится `resolutions=2` — уже есть в профиле `[div]`.
Исправление: `Core.SetCnc(true)` переключает `slashed.cfg` на 3 (Software), прежнее значение хранится в `%APPDATA%\GameRemix\games\<id>\cnc\slashed.prev` и возвращается при выключении cnc-ddraw / включении dgVoodoo. Проверка: игра с cnc-ddraw (отладочная сборка) + slashed.cfg=3 живёт 30+ с и рисует мир (снимок, FPS 57, без рамки). Известно: в cnc-ddraw не работает ползунок гаммы игры (их issue #280, лечится шейдером image-adjustment.glsl).
Компромисс: Software-отрисовка игры вместо D3D6 (вид картинки чуть другой, масштаб/сглаживание делает уже cnc-ddraw).

## Решение владельца 06.11: cnc-ddraw — основной
Строка cnc-ddraw стоит выше dgVoodoo, помечена ★ «Рекомендуется: лучшая картинка, без рамки»; в «Быстрой настройке» обёртка по умолчанию cnc-ddraw (переключатель на dgVoodoo остаётся); пресет для cnc: окно без рамки, пропорции, VSync, фильтр «Мягко» на OpenGL, игра в Software с разрешением по монитору. Окно «Настройки cnc-ddraw»: режим, фильтр, пропорции, VSync, лимит кадров, движок, чувствительность и «курсор выходит за окно» (devmode). Счётчика FPS в стабильном релизе v7.1.0.0 НЕТ (он есть только в experimental/debug-сборках); там же `gammacontrol` (ползунок гаммы игры).


## ddfx: форк с внутриигровым меню эффектов (06.11.2026)
**Зачем:** владелец хочет подбирать эффекты (огонь/магия/свет/гамма...) прямо в игре. Стандартный cnc-ddraw не читает `#pragma parameter` и не имеет меню, поэтому сделан форк v7.1.0.0 (MIT, лицензия и авторство cnc-ddraw сохранены в `ddfx_src\LICENSE`).
**Файлы:** `shared\cnc-ddraw\fx\ddraw.dll` (форк, 32-бит, отдельный файл, штатный `ddraw.dll.gz` НЕ заменён), `shared\cnc-ddraw\fx\dd-fx.cfg` (конфиг по умолчанию = Нейтральный). Исходники: `games\divine-divinity\fx_shader\ddfx_src\`.
**Включение (как положить программе, по аналогии с `Cnc.cs`):** копировать `fx\ddraw.dll` вместо штатного `ddraw.dll` cnc-ddraw (штатный сохранять как `ddraw.dll.stock-cnc`), в `ddraw.ini` секции `[ddraw]` строка `fx=true` (при `renderer=opengl`, дефолтный `shader=` игнорируется), `dd-fx.cfg` рядом с dll (папка игры). `fx=false`/нет строки = форк ведёт себя как штатный cnc-ddraw 7.1. Откат: вернуть `ddraw.dll.stock-cnc`.
**Клавиши (только когда окно игры активно):** F10 - меню (пока открыто, клавиши и клики не доходят до игры; GetKeyState/GetAsyncKeyState/DirectInput для игры возвращают 0), F9 - все эффекты вкл/выкл (сравнение до/после, игре не передаётся). В меню: Вверх/Вниз - строка, Влево/Вправо - значение (Shift x5, Ctrl /5), Enter/Пробел - рубильник, Backspace - значение по умолчанию, 1-5 - загрузить пресет, Shift+1-5 - сохранить текущие значения в слот, S - сохранить как текущие (`[current]`, читается при старте), R - сбросить к Нейтральному, Esc - закрыть. Строка «Счётчик FPS» включает FPS в правом верхнем углу, строка «Маска» показывает, что шейдер считает огнём/магией/светом (для подбора порогов).
**Формат dd-fx.cfg v1:** INI, `[current]`, `[slot1]`..`[slot5]` (слоты: только если пользователь сохранял; иначе встроенный пресет), строки `ключ=число` (bool 0/1). Неизвестные ключи игнорируются, отсутствующие берут Нейтральный. Ключи (с ddfx 1.1): `fx fire_on fire_bloom fire_v fire_s fire_radius flicker light_on light_str light_radius light_tone light_sparse ambient magic_on magic_bloom magic_v magic_s magic_green exposure gamma contrast saturation warmth vignette sharpen ui_height debug show_fps`. Версия форка в `fx.h` (`FX_VERSION`), формат конфига помечен в первой строке `; ddfx config v1`.
**Встроенные пресеты (ddfx 1.1, 07.11.2026):** 1 Нейтральный, 2 Свечение (огонь и магия), 3 Эмбиент (свечение + тёплый свет вокруг огня + лёгкое затемнение вдали от него), 4 Ночь (сильнее свет и затемнение, виньетка), 5 Полный (Эмбиент + контраст, резкость, виньетка). Старые однопроходные `.glsl` для штатного cnc-ddraw (`fx_shader\shaders\dd-N-*-bilinear.glsl`) остались от 1.0 и дают «точки»: не использовать.

**ddfx 1.1 — настоящий bloom (07.11.2026).** В 1.0 свечение считалось за один проход: 24 выборки по кругу с поворотом на каждый пиксель, поэтому вокруг свечей и факелов были точки (жалоба владельца). Теперь `fx_bloom` (fx.c) перед основным проходом: PRE (маска огня/магии по каждому пикселю, 1/2 размера; a = доля огня для света) → DOWN ×4 → UP ×4 (dual-filter, RGBA16F) → основной проход берёт уровень 0 (свечение) и уровни 1/8–1/16 (тёплый свет, `light_radius` смешивает их). Новый параметр `ambient` — затемнение вдали от огня, только в тёмных местах (проход LUMA: средняя яркость кадра; на улице не действует). Защита интерфейса — прямоугольник панели по центру снизу (`ui_height`×900 игровых пикселей в высоту, ±336 по ширине), а не вся нижняя полоса. Свечение огня дают только почти белые по яркости пиксели (волосы, золото не светятся). Мерцание — плавные волны по времени (было по клеткам по номеру кадра: блоки и зависимость от FPS). `fire_radius` = доля широких уровней (Scatter), `magic_radius` убран. Нет float-FBO или шейдер прохода не собрался — свечение/свет выключаются, остальное работает. Офлайн-копия конвейера: `fx_shader\tools\glrender2.py <пресет>` → `fx_shader\compare2\`. Программа меняет DLL эффектов у пользователей, у которых в игре нет метки `u_light2` (Fx.cs `FxMark`).
**ddfx 1.2 — настоящие источники света игры (07.11.2026).** Цвет пикселя не отличает лампу от подсвеченного текста меню, золота, освещённых NPC (владелец отверг). Теперь `fx.c` берёт огни у самой игры (разведка `docs/recon/2026-11-07_lights_recon.md`):
- **Перехват.** `fx_game_present()` (поток игры, из `ddsurface.c` — Flip/Blt/BltFast/ReleaseDC/Unlock первичной поверхности) проверяет, что это div.exe 1.0.0.62 (база 0x400000 + байты `8B 0D 58 6A 74 00 8B 11` у 0x40113e), и, когда `*(void**)0x746a58 ≠ 0`, ставит 6 своих функций в слоты vtable рендерера +0x48..+0x5c (VirtualProtect; проверка на каждом Present → после пересоздания рендерера ставится заново). Перехватчик `__fastcall(self, edx, rec)` = `__thiscall` с одним аргументом: копирует запись и зовёт оригинал. Вся работа с памятью игры — под `__try`.
- **Запись огня.** Берутся только type 0 (normal: радиус = maxrad +0x30) и type 5 (cylinder: середина POSITION..POSITION2, maxrad +0x3c); радиус 4..600 (кристаллы FD = 1000 отброшены). Экран: `sx = W/2 + dX + dZ/2`, `sy = H/2 − dZ/2 − h` (W/H из 0x64d9b8/bc), отсев за краем ±R, дубли в кадре отброшены, максимум 64. Сила = +0x24, если +0x20 (модуляция) — так мерцание идёт в такт игре.
- **Вид огня по имени light.lib** (адрес записи ищется в `lib[0][i].rec`, `*(int**)0x658c5c`): 0 лампа/огонь (`Default Light`, `Castle Light`, `Witch Dungeon Light`, `FirePlace`, `Fire`, `Burning Wagon light`), 1 магия мира (`Orb Light`, `Big/huge blue light`, `Star Blue light`, `COS *`), 2 заклинания и эффекты (всё прочее), 3 только метка, не светит (`Money Light`, самоцветы, `Monster light`, `Player *` и запись не из библиотеки = свой огонь агента: герой, монстры).
- **Кадр.** Список копится в сборщике и публикуется на Present под критической секцией (двойной буфер); второй Present того же кадра без новых вызовов список не трогает, кадр без огней 250 мс — список пустеет. `*(int*)0x658d28 != 1` (меню, дневник, карта, загрузка) → список пуст и шейдер выключен целиком (`u_world`). Ночь: `u_night = 1 − T[7]/320`, `T = *(int**)0x658c24` (под землёй игра сама даёт ночь). Поток рендера берёт копию в `fx_bloom`/`fx_frame` → uniform-ы `u_ln`, `u_lp[64]` (x, y, радиус, высота), `u_lc[64]` (rgb, a = сила + 10·вид), `u_night`, `u_world`.
- **Шейдер.** Свечение = ореол у каждого огня (`halo`, размер от `fire_radius` и радиуса огня) + bloom только ярких пикселей (≥ `fire_v`) в ядре огня (PRE). Тёплый свет = мягкое радиальное пятно `(1−d²)²` радиусом maxrad×`light_radius`, центр опущен к земле на `light_drop`×высоту, форма `light_shape` 0 круг … 1 наклонный эллипс 3D-метрики рендерера `(x+y)² + 4y²` (какая верна — проверить вживую). Сила свечения и света × `mix(day_level, 1, ночь)`: ночью в 1/day_level раз сильнее. `ambient` — затемнение вдали от огней × ночь (вместо средней яркости кадра). Поиск огня по цвету (1.1) остался только как отладка: `color_mask=1` и огней нет.
- **Новые ключи:** `halo light_shape light_drop day_level spell_lights color_mask show_lights` (старые ключи все на месте, Fx.cs совместим). `magic_on` теперь = магические огни мира, `spell_lights` = огни заклинаний (по умолчанию выкл). `show_lights` = метки (кольцо + крест в точке огня, тонкий контур пятна; жёлтый лампа, голубой магия мира, пурпурный заклинание, серый герой/золото) и строка `lights N/M night X` справа вверху (N огней, M вызовов за кадр; `no-hook` — перехват не встал, `menu` — не мир).
- **Офлайн:** `glrender2.py <пресет> [кадры] [--lights file.json] [--night 0..1] [--markers] [--menu]`, в `SYNTH` огни, расставленные вручную по факелам кадров dungeon_room и road_night.

**Устройство:** `src/fx.c` - параметры/конфиг/ввод/меню (программная отрисовка панели растровым шрифтом в RGBA-текстуру, затем один прямоугольник OpenGL с блендингом поверх кадра), `render_ogl.c` - при `fx=true` строит встроенный шейдер (`fx/fx.glsl`, одинаковый для игры и офлайн-тестов), выставляет uniform-ы каждый кадр, рисует оверлей после прохода шейдера. Нужен OpenGL 3+ (как и любые шейдеры cnc-ddraw). Стоимость кадра 4K на RTX 5070 Ti около 4 мс при включённых огне, свете и магии, ~0 при выключенных (F9 или `fx=0` в cfg: ранний выход по `u_fx`).
**Проверено:** сборка MSVC, тестовый DirectDraw-хост (16-бит 1920x1080 с кадром игры): меню, Cyrillic-текст, пресеты, сохранение в cfg и слоты, F9 (до/после побитово совпадает с Нейтральным), загрузка `[current]` при старте. НЕ проверено в самой игре (запуск без разрешения владельца запрещён): блокировка клавиш игры по меню, совместимость с реальным потоком кадров. Диагностика «всё жёлтое и светлое» на оффлайн-кадрах не воспроизводится: Нейтральный пресет не меняет картинку, поэтому для подбора есть меню и маска.

## Размер интерфейса / масштаб кадра (06.11.2026)
`Core.ApplyScale(pct, монитор)` (`src/Scale.cs`): при включённом cnc-ddraw пишет разрешение игры = монитор/масштаб в config.div и slashed-*.cfg, а в ddraw.ini: `windowed=true, fullscreen=true, maintas=true, renderer=opengl, shader=` (`Nearest neighbor` при целом растяжении, иначе `lanczos2-sharp.glsl`). Окно: «Настройки cnc-ddraw» → «Размер интерфейса» (сводка «Игра W×H → монитор M×N» и предупреждения), «Быстрая настройка» (по умолчанию Авто). Таблица: 4K → 1920×1080 (200%), 1440p → 2048×1152 (125%), 1440p@150 → 1704×958, 1080p → 1920×1080 (100%), 1080p@150 → 1280×720, 1080p@200 → 1064×600 (упор в минимум 800×600), 3440×1440 → 2752×1152, 5120×1440 → 3840×1080. Откат — «Откатить всё».

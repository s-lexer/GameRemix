# Наборы ассетов (asset sets)

Общий механизм (06.11.2026), одинаковый для всех игр: готовые «наборы файлов» (сейчас — «Улучшенная графика», потом — скины интерфейса) раздаются с НАШЕГО сервера архивами, программа скачивает их по согласию пользователя, проверяет SHA-256, атомарно подменяет файлы в папке игры, хранит копию оригиналов и откатывает одной кнопкой. Юридический вопрос раздачи решает владелец (программа пока нигде не распространяется).

Код: `src/AssetSets.cs` (игронезависимый `AssetSets`, `AssetManifest`; окно `AssetsForm`; к DD привязан только `partial class Core`: id игры `divine-divinity`, процесс `div`), `src/Net.cs` (`DownloadResume`, `GetFrom`). Сборка наборов: `shared/assets/build_asset_set.py`. Публикация: `deploy/publish_assets.sh`. Данные игры: `games/<id>/assets/<набор>.set`.

## Адреса на сервере
```
https://gameremix.pro/assets/<игра>/catalog.txt              список наборов
https://gameremix.pro/assets/<игра>/<набор>/manifest.txt     манифест
https://gameremix.pro/assets/<игра>/<набор>/<версия>/<путь>.gz|.bin   файлы (неизменяемые: новая версия — новая папка)
```
`public_html/assets/…` (nginx отдаёт `.gz/.bin/.txt` сам, с Range). Для тестов адрес каталога заменяется переменной `OGF_ASSETS_URL` (тогда разрешён http, но только на 127.0.0.1).

## Манифест (`manifest.txt`, UTF-8, строки `ключ=значение`, `#` — комментарий)
```
OGF-ASSET-SET 1
id=clean-v2                      [a-z0-9._-], до 41 знака; = имя папки на сервере
game=divine-divinity             id игры (папка games/<id>); программа берёт только наборы своей игры
version=2                        меняется при каждой пересборке (папка файлов = версия)
kind=graphics                    группа: наборы одной группы заменяют друг друга; разные группы (graphics, ui-skin …) живут рядом, если не делят файл
name.ru= / name.en=              название
desc.ru= / desc.en=              описание до ~35 знаков (в строку окна добавляется « · размер»)
size.download= / size.installed= справочно (программа считает сама по строкам file=)
file=<путь в папке игры>|<url>|<enc>|<размер упак.>|<sha256 упак.>|<размер>|<sha256 файла>|<sha256 оригинала>
```
- путь — относительный, с `\` (или `/`), без `..`, диска, `: * ? " < > |`, не оканчивается на `.ogf-new/.ogf-old/.part/.tmp`;
- url — относительно манифеста (или полный, но только на тот же хост и порт, иначе набор отклоняется);
- enc — `gzip` (один поток, `mtime=0`, уровень 9) или `raw` (тогда упакованные размер/хэш равны исходным; файлы лежат как `<путь>.bin`);
- **совместимость**: `sha256 оригинала` — список через запятую (несколько изданий игры: GOG/Steam/…); набор применяется только если у игрока файл совпадает с одним из них. `-` = файл НОВЫЙ (в оригинале его нет: при откате удаляется; если в папке уже лежит другой такой файл — отказ);
- предел: ≤ 64 файлов, упакованный файл < 2 ГБ (докачка на int-смещениях .NET 3.5), набор ≤ 8 ГБ.

`catalog.txt`: `OGF-ASSET-CATALOG 1` + строки `set=<id>`.

Скины интерфейса: тот же формат, `kind=ui-skin`, в `file=` — файлы интерфейса (оригинал есть — заменяется с бэкапом, нет — `-`). Из папки скина получаются так же: описатель `games/<id>/assets/<скин>.set` (`src`, `include`, `orig`) → `build_asset_set.py --info …`.

## Сборка (без загрузки на сервер)
```
python shared/assets/build_asset_set.py --info games/divine-divinity/assets/clean-v2.set [--orig "X:/GAMES/Divine Divinity"] [--out dist/assets] [--compress auto|gzip|raw]
python shared/assets/build_asset_set.py --verify dist/assets/divine-divinity/clean-v2
```
Описатель `.set`: `id, game, version, kind, name.*, desc.*, src (папка с раскладкой как у папки игры, от корня проекта), include (подпапки через ;), orig (папки с оригиналами, можно несколько; допустима «плоская» папка из одних имён файлов)`. Скрипт считает хэши, ищет оригинал каждого файла (в `--orig` без учёта регистра), сжимает (gzip; `auto` берёт gzip, только если выигрыш ≥ 5%), пишет `dist/assets/<игра>/<набор>/<версия>/…`, `manifest.txt` и `catalog.txt`. Если оригинала не нашлось — файл считается новым (в выводе пометка `NEW`).

Сжатие: архивы CPacked уже LZO-сжаты, но gzip всё равно даёт ~24% (CPackedb.1c 464→360 МБ), индексы `CPackedi` — в 3–10 раз. Набор `clean-v2`: 618 МБ → **472 МБ** загрузки (22 файла, 11 пар).

## Публикация (решение владельца с 1.0.18): ТОЛЬКО `sh deploy/publish_set.sh <набор>`
Файлы набора — в GitHub Releases `s-lexer/gameremix-assets` (тег `<набор>-<версия>`, плоские имена a__b), каждый файл скачивается обратно и сверяется с манифестом (размер, sha256); на VPS gameremix.pro — только `manifest.txt` с `alt=<url релиза>/` и `catalog.txt` (последним), затем смоук. `DRY=1` — только проверка сборки. Старый `deploy/publish_assets.sh` (всё на VPS) отказывается без `FULL_VPS=1`.

### Старый способ (всё на VPS, не использовать)
```
sh deploy/publish_assets.sh              # все наборы из dist/assets/divine-divinity
DRY=1 sh deploy/publish_assets.sh        # только проверка (хэши + место на сервере), ничего не грузит
```
Порядок: проверка хэшей локально → место на сервере (нужно 2× размер + 2 ГБ) → докачиваемая загрузка (sftp `put/reput`) в `/tmp/ogf-assets-incoming/…` → `sha256sum -c` на сервере → папка версии → `manifest.txt` → `catalog.txt` последним → смоук (манифест байт в байт, размер/Range/отсутствие перекодирования у каждого файла). Старые версии набора: хранятся две последние. Каталог на сервере = то, что собрано в `dist/assets/<игра>` (собирать все наборы на одной машине).

## Клиент: что делает «Применить»
1. Игра не запущена (процесс игры), папка записываемая. Незавершённая прошлая замена (запись `applying`) откатывается.
2. **Совместимость по хэшам** (с кэшем «путь+размер+время → хэш», 500 МБ читаются один раз): каждый файл игры (или его резервная копия) должен совпасть с оригиналом из манифеста; иначе отказ ДО скачивания, со списком файлов.
3. Место на дисках (папка игры, профиль, кэш).
4. Скачивание в `%LOCALAPPDATA%\GameRemix\cache\assets\<игра>\<набор>-<версия>\` по одному файлу, с докачкой (Range; при обрыве `.part` остаётся и до 5 попыток, пока идёт прогресс), SHA-256 упакованного файла; кэш остаётся (повторно не качаем).
5. Распаковка рядом с целью (`<файл>.ogf-new`, тот же диск), проверка SHA-256 содержимого.
6. Резервная копия оригиналов `GameData\assets\<набор>\orig\<путь>` — только если её ещё нет и файл — оригинал; существующая копия никогда не перезаписывается (если она не совпала с оригиналом — отказ).
7. Запись `active.txt` (`applying`) → подмена (`файл → .ogf-old`, `.ogf-new → файл`); любой сбой возвращает всё; запись → `applied` (размер/время каждого файла); `.ogf-old` удаляются.
Файл, изменённый после применения (DGE, ручная правка, обновление игры), не перезаписывается и не откатывается молча — отказ с пояснением; резервная копия остаётся.

**Откат** (`Откатить` / `--assets revert` / «Откатить всё»): файл = применённый → возвращается копия оригинала (проверка хэша, атомарно, с откатом отката); уже оригинал (переустановка) — пропуск; новые файлы набора удаляются; если всё вернулось — папка набора с бэкапом удаляется, иначе остаётся запись и копии только для невозвращённого.

**Состояние** (по хэшам): `original` / `applied` / `mixed` / `unknown` (CLI `--assets status`). Главная страница показывает быстрый статус без хэширования (размер+время из записи): включено / изменено / не завершено / оригинал.

## CLI
`--assets list` · `--assets status` · `--assets apply <id>` · `--assets revert <id>` (+ `--game DIR`, `--lang ru|en`, `--log FILE`); строки результата: `ASSET id=… version=… download=… installed=…`, `ASSET-STATUS id=… state=… applied=N original=N other=N missing=N`, `ASSETS active=<id,…|none>`. Код выхода: 0 / 1 ошибка (в т. ч. несовместимо, обрыв) / 2 аргументы / 3 игра запущена / 4 нет прав. `--revert-all` включает откат наборов. Тестовые переменные: `OGF_ASSETS_URL`, `OGF_ASSETS_FAILSWAP=N` (сбой после N подмен), `OGF_CACHE`, `OGF_DATA`.

## Безопасность
Только https (TLS 1.2) и только `gameremix.pro` (резерв — `gameremix.speectra.com`); файлы — только с хоста/порта манифеста; нет кэша WinINet; манифест ≤ 256 КБ; лимиты размеров; все хэши проверяются; пути из манифеста и из записи нормализуются и не могут выйти из папки игры. Манифест сам не подписан (доверие — TLS нашего сервера); подпись манифеста — задача на будущее.

## Слои, зависимости, превью (06.11.2026, вкладка «Графика»)
Новые необязательные ключи манифеста (`build_asset_set.py` берёт их из `.set`): `layer=N` (0..9; по умолчанию graphics = 0, ui-skin = 1) — порядок стопки: набор верхнего слоя ставится ПОВЕРХ нижнего, даже если делят файл (его список оригиналов должен содержать хэш файла нижнего набора, иначе несовместимо); `requires=id,…` и `conflicts=id,…` — зависимости и несовместимость наборов; `preview=id|url|w|h` — картинки превью (пока встроены в программу). Откат нижнего слоя сначала откатывает верхние; «Откатить всё» — от верхних к нижним. Сборка скинов: `games/divine-divinity/assets/skin-*.set` (`orig=` — оригиналы И файлы набора под ними). Модель выбора и плана — `src/Gfx.cs`.
